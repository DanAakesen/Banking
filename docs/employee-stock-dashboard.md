# Employee shares: vesting dashboard and fictional Demo

## Design and status — 16 October 2026

Scope is `section#employee-stock-preview` on Investments. The existing scenic header, Saxo portfolio/trading selector and separate manual investments remain intact. The Accounts-aligned panel now leads with held-now, source-unvested and next-vesting quantities, followed by a calendar chart. The summary and selected point fit within one working desktop viewport. Upload/review, valuation settings, source rows, warnings, originals, employment/archive declarations and report history are collapsed behind named actions/details. Technical parser/byte information appears only in report details.

Monthly bins retain empty calendar intervals; default is the current month plus eleven months, with events filtered inclusively from today. An optional 24-month range and all-upcoming range are available. Yearly view sums those same source events. A history option adds actual reported `StockAwardVest` transaction dates, distinguished from conditional scheduled events by separate styling and legend. Scheduled weekend dates and business-day deliveries retain their separate dates. Long histories use yearly bins rather than an unreadable monthly plot. Arrow/Home/End keys and touch select points; exact source dates/quantities and an optional illustration appear below. A collapsed keyboard-scrollable table provides an alternative.

Currency/period/range/point interactions use loaded data only. USD uses the explicitly dated USD-per-share price; DKK additionally multiplies by DKK per **one USD**. Unknown or invalid assumptions keep the useful share chart and label valuation unknown. Illustrations are conditional gross values at a reviewed price, not forecasts, tax-net proceeds or current wealth. Held-now declarations remain separate from source vested history. Archiving retains originals/history and collapses the future source view; no date change creates deliveries or forfeits vested ownership.

## Exact normal-API application contract

Main/Luna first reviews and publishes this source, then independently verifies the full hosted `git-<40-character-main-SHA>` build and existing release gates. Only afterward, in Banking Cloud:

```bash
python3 scripts/setup-demo-employee-stocks.py \
  --expected-build git-<verified-main-SHA> --plan artifacts/employee-stock-demo-plan.json
# Inspect ready:true, the exact build, three dated operations, target mapping and protected baseline.
python3 scripts/setup-demo-employee-stocks.py \
  --expected-build git-<verified-main-SHA> --plan artifacts/employee-stock-demo-plan.json --apply
# Repeat both commands: operations:[] and applied:0, with no new receipts/products/points.
```

The script creates a fresh memory-only Demo session at the fixed Azure origin. Strict path/method guards exclude owner uploads, original downloads, SQL, reset, sync, orders and unrelated financial writes. It requires one active product-demo connection, five synthetic accounts and the exact verified build. The immutable reviewed plan binds receipts, current product/version, build and protected accounts/budgets/goals/other wealth (including pension). A missing product is created once; an existing mapping must be proven by accepted synthetic reports, expected values and the private managed-product projection. Unknown manual Microsoft records, edits, deleted mappings, changed plans/builds or unresolved reports stop safely. Pending generated receipts can be reused. Repeated setup makes no further writes; canonical history has exactly three dates and one latest product.
