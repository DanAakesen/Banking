## Licence duties beyond the declarations

These entries summarize all licence sections that affect operation or acceptance; implementation suggestions are our interpretation, not additional verbatim Saxo requirements.

- **Scope and users (preamble, 1.5, 2.1):** personal, non-transferable access for own-account/internal use; the text excludes general third-party applications. LIVE must remain Dan-only. Do not assume that this LIVE licence also authorizes publicly shared broker-backed SIM trading or market-data redistribution. Dan's workplace demonstrations and existing public Demo need a separate scope check with Saxo; no restriction was changed during this review.
- **Promotion, IP and statements (2.2, 3, 12, 14):** Saxo may mention the app; respect its IP and do not imply partnership/endorsement. The licence restricts public announcements about the agreement without consent. Check branding and presentation plans; fictional-demo product design alone does not resolve licence questions.
- **Responsibility and risk (4, 5, 8.5, 8.9):** the operator bears app/transaction/security responsibilities and specified indemnities; information may be incomplete or outdated. The displayed Saxo liability cap is EUR 20,000 per twelve months. These are owner acceptance considerations, not something a passing test transfers away. Keep freshness/quality visible and make uncertain execution states explicit.
- **Termination and exceptional markets (6, 7):** access may be withdrawn, limited or ended. Provide an operational disable/disconnect path, stop provider calls appropriately, label any retained snapshot, and explain the outage. Never turn a failed request into a zero position or silently switch environments.
- **Authentication and access (8.1–8.4):** protect app credentials; use Saxo's own login, never collect/proxy Saxo passwords; refresh tokens are for direct token renewal only; monitor and restrict API use. The current code has single-use expiring OAuth state and exact return URLs. Before LIVE, verify that authorization initiation, callback completion and saved-token ownership remain tied to the authorized owner and intended environment; current pending-state data records market/return URL but not an owner-session identity.
- **Correctness and isolation (8.6–8.8):** accurately present positions, orders, holdings, margin, confirmations and quotes; never execute for or expose one user's account to another; respect applicable rules and additional API/exchange terms, and provide requested compliance information. Test forged environment/mode headers, logout, expired sessions, copied callback links, cross-tab switches and advisor access. Partition caches/snapshots/AI context by authorized owner and environment; clear visible private data when switching to Demo.
- **Ongoing testing and verification (9, 10):** continue SIM testing after LIVE activation, retain reproducible evidence and be able to demonstrate compatibility and correct user operation. SIM service incidents may be lower priority than LIVE. Test service windows and degradation without submitting orders.
- **Service changes and notifications (11):** track API changes and notify the user about material disruptions. The modal says Saxo attempts at least 30 days' notice for incompatible changes; the linked version policy describes a typical three-month notice. Neither is an unconditional uptime or notice guarantee. Maintain a release/deprecation register.
- **Agreement structure and acceptance (13–16):** severability, no implied agency/partnership, Danish law/courts and binding acceptance; an organizational signer must have authority. These require Dan's own review/acceptance rather than an app feature. The terms are not accepted by this note.

## Concrete implementation order

1. **Private LIVE read boundary:** preserve SaxoAccess owner checks; add an explicit server-approved environment to Investments/360 read contracts, sign-in, caching and advisor tools. Current Investments calls are hardcoded SIM, the combined portfolio route calls RequireSim, and SaxoPortfolio labels its response SIM. Simply installing LIVE credentials cannot make that page LIVE-ready. Keep all write routes SIM-only for now. Test that Demo cannot obtain LIVE data through any route.
2. **OAuth and session lifecycle:** verify owner/state binding, refresh races, expiry, revoked access, disconnect and secret redaction. Store credentials once in Azure; localhost remains frontend-only.
3. **Provider request controls:** enforce Saxo-aware rate budgets and shared safe-read requests, visible stale/error states, no retry storms and no uncertain-write replay.
4. **Data/UI acceptance:** fixtures for all table cases above, then owner-authorized LIVE reads compared with Saxo's platform. Test SIM/LIVE transitions and layout in both frontends. No real-money order is needed to validate data access.
5. **Operations and licence scope:** maintain the test/incident/deprecation record; clarify demonstration/shared-SIM/data-use scope; Dan decides on terms. Only after separate LIVE-trading approval implement and validate the remaining execution controls.

This review authorizes no code release, credential installation, live transaction or terms acceptance. It records the work needed; implementation status must be updated with concrete evidence rather than assumed from this checklist.
