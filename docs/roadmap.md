## AI features — next priority and proposed voice experience

Dan confirmed all six additions discussed on 13 September: budget maintenance (AI-07), deviation explanations (AI-08), interactive what-if analysis (AI-04), assisted Review (AI-09), proactive insights (AI-10), and user-controlled memory (AI-11). He selected persistent voice (AI-12) ahead of these. The two visual states were approved on 13 September, with a thin reddish border matching Stop. The persistent companion is implemented locally; the following records the accepted direction.

- **One conversation, three presentations:** the existing Overview pane, a compact floating voice control, and an expanded chat overlay. Starting voice in the pane activates the same session indicator. Navigating away or minimizing chat leaves the floating control at the lower right. Returning to Overview reuses the same conversation without reconnecting or duplicating controls.
- **Shared visual language:** a restrained animated waveform in a small theme-aware pill, reused beside the composer in the chat pane. Distinguish connecting, listening, speaking, working and reconnecting from actual session/tool events. Audio motion follows measured levels where available; idle decoration must not imply detected speech. Provide a static reduced-motion equivalent.
- **Discoverable controls:** desktop hover or keyboard focus reveals Open chat and a red Stop button; clicking the pill also opens chat. On touch, tapping reveals the controls. Stop remains directly accessible in expanded chat. Minimize/close collapses chat while voice continues; Stop ends voice, releases the microphone and preserves the transcript. Never rely on hover alone.
- **User-confirmed movable control:** Dan approved the direction and requested free dragging, like Codex pets. The lower-right corner is only the initial position. Support mouse and touch dragging; a drag must not open chat or activate Stop. Preserve the chosen position across in-app navigation and remember it locally for the next visit. Keep the complete control within the visible viewport and safe areas after resizing or rotation, without forcing it to snap to a corner. Provide keyboard repositioning and a reset-position action. The chat overlay remains a separate presentation; moving the pill does not move or restart the voice connection.
- **User-confirmed mini captions:** show only the assistant's current spoken text in a compact bubble of one or two lines near the movable control. Replace the previous text as new speech arrives; do not build a scrolling transcript in mini mode or display the user's speech there. Retain the full conversation in expanded chat. Include clear expand/minimize controls and the drag grip. Dan requested two design previews: mini and fully expanded, before implementation.
- **Stay on the current page:** opening chat uses a compact right overlay with Expand available, so the user can still inspect the budget, accounts or goals. Mobile uses a near-full-screen overlay and respects safe areas. Preserve the existing clean messages, history overlay and generative artifacts, without adding a second activity bar.
- **Changes visible in context:** after a confirmed tool write, refresh the affected page data and briefly emphasize the changed record with a subtle background fade and concise confirmation. Preserve scroll, filters and unsaved form edits; if a form is dirty, show that fresh data is available instead of overwriting it. Do not navigate away automatically or show a successful change before it is committed.
- **Persistent ownership:** move advisor/voice ownership outside the route content that is currently replaced during navigation. Keep the same connection and iframe alive, changing presentation without reparenting/reloading it. Send the current page, selected records and filters as structured, authenticated context when relevant; do not silently reinterpret an explicit earlier request. Theme and text sizing still come from Banking.
- **Boundaries and acceptance:** sign-out, workspace change and explicit Stop end the call. In-app navigation/minimizing must not interrupt it. Full browser reload/closing the tab and mobile OS suspension are separate lifecycle cases, not promised seamless continuation. Test Overview → Budgets → Goals during one call, open/minimize/expand, an AI-created Demo budget entry appearing on the viewed page, microphone release, touch/keyboard controls, all themes and reduced motion.

## AI design direction

- **Primary requirement: generative UI.** The agent authors the presentation; reusable cards must not be the only output route. First prove the artifact renderer, persistence and phone/theme behavior with Demo data. See [generative advisor UI](generative-advisor-ui.md).
- Banking and its financial system of record stay in Azure. An **OpenAI-hosted** agent sandbox runs outside that subscription. This is a proposed external processing boundary, requiring a decision about data handling, retention/residency and allowed datasets before real financial data is sent. Do not assume these APIs are available through Azure OpenAI.
- Expose authenticated, workspace-scoped read-only tools and only the data needed for a question. Give the sandbox no bank secrets, database credentials or unrestricted database access. Analysis artifacts do not edit authoritative financial records.
- Keep canonical financial facts in Banking's trusted tools. Allow new agent-generated analyses in the authorized sandbox, with visible inputs, assumptions and validation of consequential results. Show baseline, changed inputs, period and currency. Missing data remains visible. Saving a scenario, if added, is a separate explicit user action.
- Start with synthetic Demo data. Anonymous Demo must not grant unlimited paid AI use: choose caps or previews before public activation. Isolate AI history, files, audio and cached responses between workspaces.
- Review voice/analysis UX together before implementation. Preserve the compact overlay, existing styling, five themes and phone usability. Interactive analysis does not imply real-time market feeds.
